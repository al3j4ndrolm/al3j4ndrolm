# Facet 1.0

A Mac app for building Android apps with Jetpack Compose. Design screens on a canvas, write your ViewModels in Kotlin, connect taps to events, and run the result on a phone or emulator.

Every Facet project is a normal Android Studio project. You can open the same folder in Android Studio at any time.

## What you can do

| | |
|---|---|
| **Create** | New Project wizard with two templates: an empty app, or a coffee-shop sample with 3 screens. Facet writes a complete Gradle project (AGP 8.13, Kotlin 2.2, Compose BOM 2025.12, type-safe Navigation, Coil). |
| **Design** | Canvas with auto layout, sizing, Material 3 color and type tokens, 13 components (text fields, switches and lazy lists included), drag to reorder, resize handles, light/dark preview. |
| **Logic** | Each screen uses one ViewModel. You write it in Kotlin; Facet reads its `UiState` fields and `Event` interface, so state appears as bindings and events appear as click actions. |
| **Navigation** | Screens with typed route arguments, a start destination, enter transitions (fade, slide, slide up, scale) and a Flow view of every link. |
| **Run** | **⌘R** saves, runs `./gradlew installDebug` on the selected phone or emulator (Facet can boot an AVD), launches the app and streams logcat. Kotlin compiler errors show up in Problems; click one to open the line. |
| **Prototype** | **⌘↩** taps through screens and transitions on the canvas, using the preview data. Events are logged. |

## Requirements

- macOS 13 or later, Apple Silicon or Intel.
- [Android Studio](https://developer.android.com/studio) installed once. It installs the Android SDK and ships a JDK. Facet finds both automatically, or you can set them in **Facet › Settings** (⌘,).
- To run on a phone, turn on USB debugging ([guide](https://developer.android.com/studio/run/device)). To use an emulator, create one in Android Studio's Device Manager.

## Project layout

```
MyApp/
├── facet.json                  ← the design: screens, layers, theme, preview data
├── app/src/main/java/…/
│   ├── ui/<screen>/XScreen.kt  ← generated from the canvas
│   ├── ui/<vm>/XViewModel.kt   ← yours. Facet edits it only when you do.
│   ├── navigation/NavGraph.kt  ← generated
│   ├── ui/theme/Theme.kt       ← generated
│   └── MainActivity.kt         ← generated
├── app/src/main/res/font/      ← the theme's fonts, bundled (OFL)
└── gradlew, build.gradle.kts, gradle/libs.versions.toml
```

Generated files start with `// Generated by Facet`. Facet rewrites them on every save and removes ones whose screens you delete. Edits made in Android Studio to your ViewModels are picked up when you switch back to Facet.

## Develop Facet

```sh
cd facet-studio
npm install
npm start          # run from source
npm run dist       # dmg + zip for Apple Silicon and Intel → dist/
```

Pushing changes under `facet-studio/` builds signed-for-local-use (ad-hoc) DMGs on a macOS runner (`.github/workflows/facet-studio-mac.yml`). Download them from the run's **Artifacts**.

### First launch of a downloaded build

Builds are ad-hoc signed and not notarized, so macOS quarantines them. Drag `Facet.app` to Applications, then right-click → **Open**, or run:

```sh
xattr -cr /Applications/Facet.app
```

For public distribution, sign with a Developer ID certificate and notarize (`mac.identity`, `hardenedRuntime: true`, `notarize` in `package.json`).

## Architecture

| Path | Role |
|---|---|
| `src/core.js` | Shared by the editor and main process: the project model, Kotlin ViewModel parser, Compose/Navigation/Theme code generation and the Android project template |
| `src/app/*.js` | Editor UI (sandboxed renderer, strict CSP, fonts bundled offline) |
| `main/index.js` | Windows, native menus, settings, recents and the run pipeline |
| `main/project.js` | Create, open and save project folders; cleans up stale generated files |
| `main/android.js` | Finds the SDK and JDK; handles devices and AVDs, Gradle, install and launch, and logcat |
| `templates/` | Gradle wrapper (8.14.3) and fonts converted to TTF for `res/font` |

## Limits in 1.0

- The canvas approximates Compose in HTML. The device is the source of truth.
- Screens are edited on the canvas only. Hand edits to generated screen files are overwritten on save.
- The ViewModel parser reads standard patterns (`data class XUiState`, `sealed interface XEvent`, `val state: StateFlow<…>`, `fun onEvent(event: XEvent)`).
- Fonts cover Latin scripts.
